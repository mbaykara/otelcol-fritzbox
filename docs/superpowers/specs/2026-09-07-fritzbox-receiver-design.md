# Fritz!Box OpenTelemetry Receiver — Design

Date: 2026-09-07
Status: Approved (metric contract, architecture, config)
Author: Mehmet Baykara + OpenCode

## 1. Goal

A custom OpenTelemetry Collector **metrics receiver** that scrapes AVM
Fritz!Box (and Fritz!Repeater) routers via their built-in **TR-064 API** and
emits metrics in OTel format, so Fritz!Box telemetry can flow through any
Collector pipeline (OTLP, Prometheus, etc.).

Existing Prometheus exporters (pdreker/fritz_exporter, sberk42/fritzbox_exporter)
prove the data is available; this project is the native OTel equivalent.

### Non-goals

- No Lua/web-UI API scraping (undocumented, fragile across firmware).
- No traces or logs — metrics only.
- No write operations (port mappings, reboots, config changes) — read-only.

## 2. Decisions (locked)

| Question | Decision |
|---|---|
| Metrics scope | Core WAN/network + WiFi radios + host counts, all via TR-064 |
| Project layout | Standalone Go module importable into **any** collector via OCB |
| Approach | Contrib-style scraper: `mdatagen` + `scraperhelper` + own TR-064 client |
| Test hardware | Live Fritz!Box on the network (Fritz!OS 8.25, HW 226) + fixtures |
| Metric contract | **Mixed scheme**: released `hw.network.*` semconv where applicable, `fritzbox.*` for Fritz-specific metrics |

## 4. TR-064 client (`internal/tr064`)

- **Discovery (once at Start):** GET `http://<endpoint>/tr64desc.xml`, build a
  `serviceType -> controlURL` map. Doubles as capability detection: e.g. a
  cable/fiber box has no `WANDSLInterfaceConfig` service, so the DSL metric
  group is silently skipped.
- **`Call(ctx, service, action, ...)`:** SOAP 1.1 POST to the service's
  controlURL with the correct `SOAPAction` header.
- **Auth:** HTTP Digest (RFC 7616, MD5), implemented in-package (~60 lines).
  Fritz!Box requires authentication for all data-bearing actions. No external
  TR-064 dependency — Go has no maintained TR-064 library.
- Responses parsed into `map[string]string`; SOAP faults become typed errors.

## 5. Metric contract (final)

### 5.1 Standard `hw.network.*` (semconv, Development stability)

Source: https://opentelemetry.io/docs/specs/semconv/hardware/network/

| Metric | Instrument | Unit | Attributes | TR-064 source |
|---|---|---|---|---|
| `hw.network.io` | Counter (monotonic sum) | `By` | `hw.id`, `hw.name`, `network.io.direction=receive/transmit` | WANCommonInterfaceConfig.GetTotalBytes{Sent,Received} |
| `hw.network.packets` | Counter | `{packet}` | `hw.id`, `hw.name`, `network.io.direction` | GetTotalPackets{Sent,Received}; also WLANConfiguration.GetStatistics per radio |
| `hw.network.bandwidth.limit` | UpDownCounter (gauge) | `By/s` | `hw.id` | GetCommonLinkProperties Layer1{Up,Down}streamMaxBitRate (bit/s ÷ 8) |
| `hw.network.up` | UpDownCounter (gauge) | `1` | `hw.id`, `hw.name` | PhysicalLinkStatus; WLAN status per radio |
| `hw.errors` (network) | Counter | `{error}` | `hw.type=network`, `error.type=fec/crc/hec`, `network.io.direction` | WANDSLInterfaceConfig.GetStatisticsTotal |
| `hw.network.bandwidth.utilization` | Gauge | `1` | `hw.id`, `network.io.direction` | X_AVM-DE_{Up,Down}streamCurrentUtilization (as fraction) |

- `hw.id` is Required by semconv but the box exposes no native hardware IDs →
  synthesized: `fritzbox.wan`, `fritzbox.wlan1`, `fritzbox.wlan2`,
  `fritzbox.wlan3`.
- `hw.name` for WLAN datapoints carries the SSID.

### 5.2 Custom `fritzbox.*` (no semconv coverage exists)

| Metric | Instrument | Unit | Attributes | TR-064 source |
|---|---|---|---|---|
| `fritzbox.device.uptime` | Gauge | `s` | — | DeviceInfo.GetInfo → UpTime |
| `fritzbox.wan.connection.status` | Gauge (1=Connected) | `1` | — | WANIPConnection (fallback WANPPPConnection).GetStatusInfo |
| `fritzbox.wan.connection.uptime` | Gauge | `s` | — | GetStatusInfo → Uptime |
| `fritzbox.wan.external_ip` | Gauge=1 | `1` | `external_ip` | GetExternalIPAddress (optional metric, off by default) |
| `fritzbox.dsl.rate.current` | Gauge | `bit/s` | `network.io.direction` | WANDSLInterfaceConfig.GetInfo (unit verified vs box UI during live test) |
| `fritzbox.dsl.rate.max` | Gauge | `bit/s` | `network.io.direction` | GetInfo |
| `fritzbox.dsl.noise_margin` | Gauge | `dB` | `network.io.direction` | GetInfo (raw 0.1 dB ÷ 10) |
| `fritzbox.dsl.attenuation` | Gauge | `dB` | `network.io.direction` | GetInfo (raw 0.1 dB ÷ 10) |
| `fritzbox.dsl.error_seconds` | Counter | `s` | `severity=errored/severely_errored` | GetStatisticsTotal |
| `fritzbox.wlan.channel` | Gauge | `1` | `hw.id`, `ssid` | WLANConfiguration:1..3 GetInfo |
| `fritzbox.wlan.clients` | Gauge | `{client}` | `hw.id`, `ssid` | GetTotalAssociations |
| `fritzbox.hosts.total` | Gauge | `{host}` | — | Hosts.GetHostNumberOfEntries |
| `fritzbox.hosts.active` | Gauge (**optional**, off by default; costs N SOAP calls) | `{host}` | — | iterate Hosts.GetGenericHostEntry |

### 5.3 Resource attributes (all metrics)

`hw.vendor=AVM`, `hw.model`, `hw.serial_number`,
`fritzbox.device.software_version`, `server.address`.

### 5.4 Stability & versioning

- Component stability declared in `metadata.yaml`: `development`
  (collector ladder: development → alpha → beta → stable).
- `hw.network.*` semconv is itself Development stability — names could change
  upstream; accepted risk for standardization.
- Dependencies pinned to current collector core (`v1.x` / `pdata v1.x` /
  `v0.14x` line) in go.mod and in the OCB manifest.

## 6. Configuration

```yaml
receivers:
  fritzbox:
    endpoint: http://fritz.box:49000     # required
    username: ${env:FRITZBOX_USERNAME}   # required
    password: ${env:FRITZBOX_PASSWORD}   # required
    collection_interval: 30s             # scraperhelper.ControllerConfig
    timeout: 10s
    metrics:                             # mdatagen-generated toggles
      fritzbox.hosts.active:
        enabled: true
```

`Validate()`:
- `endpoint` must parse as an absolute URL.
- `username` and `password` required (box refuses unauthenticated calls).
- `collection_interval` > 0, `timeout` > 0 and ≤ collection_interval.

## 7. Error handling

- Box unreachable / auth failure → scrape returns error → scraperhelper logs
  and keeps the collector running; visible via collector self-telemetry
  (`otelcol_receiver_accepted/refused_metric_points`).
- Per-group failures (e.g. no DSL service on cable boxes, WLAN down) → warn-log
  once, skip group, emit all other groups.
- Static resource attributes (model/serial/version) fetched on first
  successful scrape and cached.

## 8. Testing

- `internal/tr064` unit tests against `httptest.Server` with recorded SOAP
  fixtures (anonymized).
- Scraper tests with a fake TR-064 client covering:
  full DSL box, cable box (no DSL service), WLAN radio down, auth failure.
- mdatagen-generated component test (metadata validity).
- **Live smoke test:** OCB build from `example/`, debug exporter, real
  credentials via env vars → verify datapoints in stdout against the box UI.

## 9. Go code quality bar

- Idiomatic Go per Effective Go and the Go project style:
  - errors wrapped with `%w`, never swallowed, no panics in library code;
  - `context.Context` propagated into every blocking call (HTTP, SOAP);
  - small, focused files; clear package boundaries (`tr064` client has no
    collector/pdata imports, pdata stays out of the client);
  - interfaces only where they enable testing (fake TR-064 client), not
    speculatively.
- Clean under `gofmt -s`, `go vet`, and `staticcheck`-level hygiene
  (no unused code, correct struct tags, no naked returns in long functions).
- Table-driven unit tests with `t.Run` subtests; fixtures in `testdata/`.
- No third-party dependencies beyond the collector itself and the standard
  library (TR-064 client and digest auth are hand-rolled).
